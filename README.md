# 1c-config-direct

A Claude Code skill that reads a 1C:Enterprise configuration — module source code, the object tree, attributes and
their types — straight from the database storage (the Config table in MS SQL, a 1Cv8.1CD file infobase, or a .cf/.cfe
file), without the Designer and without an XML dump.

Скилл Claude Code: читает конфигурацию 1С/BAS прямо из ее хранилища. Он берет тексты модулей, состав объектов,
реквизиты и их типы из таблицы Config серверной базы MS SQL, из файла файловой базы `1Cv8.1CD` или из файла
`.cf`/`.cfe`. Конфигуратор и выгрузка в XML не нужны, база только читается. Типичное время ответа — секунды.

Зачем: посмотреть код в копии базы клиента или в присланном `.cf`, найти, где вызывается процедура или пишется регистр,
узнать реквизиты и типы объекта, сравнить `.cf` с базой. Когда XML-выгрузки нет, она устарела или делать ее долго.

## Установка

В терминальной сессии Claude Code:

```
/plugin install 1c-config-direct --marketplace kachamkin/1c-config-direct
```

Из командной строки:

```
claude plugin install 1c-config-direct --marketplace kachamkin/1c-config-direct
```

На вопрос `Add marketplace?` ответьте `y`, затем выберите область установки. В настольном приложении, где `/plugin`
не работает: нажмите + рядом с полем ввода, затем Plugins, Add marketplace с `kachamkin/1c-config-direct`, затем Add plugin.

Можно и без плагина: скопируйте папку `1c-config-direct/skills/1c-config-direct` в `~/.claude/skills/`.

Нужен Python 3.8 или новее, сторонние пакеты не нужны. Для чтения из MS SQL нужны Windows PowerShell и доступ к SQL
Server по Windows-учетной записи. Файлы `.cf`, `.cfe` и `1Cv8.1CD` читаются без SQL.

## Что умеет

Источник — одно из трех:
- `sql:<база>` или `sql:<сервер>/<база>` — таблица `dbo.Config` базы MS SQL. Строки кешируются, при следующих
  запусках докачиваются только изменившиеся;
- путь к `.cf` или `.cfe` — файл конфигурации или расширения;
- путь к `1Cv8.1CD` или к папке файловой базы.

| Команда | Что делает |
|---|---|
| `info` | имя, поставщик, версия, режим совместимости, состав по классам, модули без текста, расширения базы |
| `objects`, `modules` | списки объектов и модулей с фильтром |
| `module <имя>` | текст модуля, можно с номерами строк и диапазоном |
| `grep <текст>` | поиск по всем модулям; `--proc` показывает процедуру, в которой стоит совпадение |
| `fields [фильтр]` | реквизиты, реквизиты ТЧ, измерения, ресурсы и т.п. с типами |
| `export <папка>` | модули в раскладке XML-выгрузки (`Catalogs/X/Ext/ObjectModule.bsl` …) |
| `diff <источник2>` | сравнение двух источников: модули и типы полей |
| `check <папка XML>` | самопроверка: сверка с XML-выгрузкой той же конфигурации |

Имена можно писать по-русски: `Справочник.Валюты.МодульОбъекта`, `ОбщийМодуль.ОбщегоНазначения`.

```bash
py -X utf8 cfgread.py sql:trade grep "ЦеныНоменклатуры" --proc --ctx 2
py -X utf8 cfgread.py "D:\Bases\Shop" module "Документ.РеализацияТоваровУслуг.МодульОбъекта" --lines 1-60
py -X utf8 cfgread.py "D:\Incoming\client.cf" diff sql:trade --fields
```

Обычно скрипт запускать самому не нужно. Попросите Claude: «посмотри модуль объекта документа ЗаказПокупателя в
базе trade», «где пишется регистр ЦеныНоменклатуры», «что поменялось в client.cf по сравнению с базой».

## Насколько можно доверять

Формат хранения 1С не документирован. Все, что знает скилл, получено опытным путем и сверено с XML-выгрузками
конфигуратора (платформа 8.3.27). Сверка прошла на семи разных конфигурациях:
- УТ 2.3 с обычными формами, УТ 3.1, УТП 1.2 с планами счетов и расчетом;
- BAS Розница, ITIL, Бухгалтерия для Украины 1.2;
- одна отраслевая конфигурация.

Источниками были MS SQL, `.cf` и файловые базы. Тексты 16 930 непустых модулей совпали с XML байт в байт, типы
64 302 полей тоже совпали. Отличие нашлось одно: ссылка на удаленный объект, которую XML-выгрузка молча
выбрасывает. Устройство хранения с таблицами констант описано в
[storage-format.md](1c-config-direct/skills/1c-config-direct/references/storage-format.md).

## Ограничения

- Читается конфигурация базы данных. Изменения, сохраненные в конфигураторе, но не примененные к базе (ConfigSave),
  и расширения, установленные в базе (ConfigCAS), не читаются; расширение можно прочитать из его `.cfe`.
- Не разбираются стандартные реквизиты и прочие свойства объектов и полей: периодичность регистров, владельцы,
  движения, индексирование, параметры выбора, права, разметка форм.
- Модули, поставленные без исходного текста или закрытые паролем, отмечаются как модули без текста.
- Файловые базы — только формат хранения 8.3.8. PostgreSQL не поддерживается.
- Современный `.cf` (примерно с режима совместимости 8.3.17) начинается с заглушки — «пустой конфигурации», —
  а настоящая конфигурация лежит дальше в 64-битном контейнере. Скилл читает ее; старые утилиты видят только заглушку.

Скилл ничего не записывает ни в базу, ни в файлы конфигурации. Проект не связан с фирмой «1С».
