# 1c-config-direct

A Claude Code skill that reads a 1C:Enterprise configuration — module source code, the object tree, attributes and
their types (standard attributes included), object properties, predefined items, rights of roles, the layout of
managed and ordinary forms and cross-references — straight from the database storage (the Config table in MS SQL, a 1Cv8.1CD file infobase, or a .cf/.cfe
file), without the Designer and without an XML dump.

Скилл Claude Code: читает конфигурацию 1С/BAS прямо из ее хранилища. Он берет тексты модулей, состав объектов,
реквизиты и их типы, свойства объектов, предопределенные элементы, права ролей, разметку управляемых и обычных форм и ссылки между
ними из таблицы Config серверной базы MS SQL, из файла файловой базы `1Cv8.1CD` или из файла
`.cf`/`.cfe`. Конфигуратор и выгрузка в XML не нужны, база только читается. Типичное время ответа — секунды.

Зачем: посмотреть код в копии базы клиента или в присланном `.cf`, найти, где вызывается процедура или пишется регистр,
узнать реквизиты, типы и свойства объекта, понять, какие документы делают движения по регистру, сравнить `.cf` с базой. Когда XML-выгрузки нет, она устарела или делать ее долго.

## Установка

В терминальной сессии Claude Code:

```
/plugin install 1c-config-direct --marketplace kachamkin/1c-config-direct
```

Из командной строки:

```
claude plugin install 1c-config-direct --marketplace kachamkin/1c-config-direct
```

На вопрос `Add marketplace?` ответьте `y`, затем выберите область установки. В настольном приложении, где `/plugin`
не работает: нажмите + рядом с полем ввода, затем Plugins, Add marketplace с `kachamkin/1c-config-direct`, затем Add plugin.

Можно и без плагина: скопируйте папку `1c-config-direct/skills/1c-config-direct` в `~/.claude/skills/`.

Нужен Python 3.8 или новее, сторонние пакеты не нужны. Для чтения из MS SQL нужны Windows PowerShell и доступ к SQL
Server по Windows-учетной записи. Файлы `.cf`, `.cfe` и `1Cv8.1CD` читаются без SQL.

## Что умеет

Источник — одно из трех:
- `sql:<база>` или `sql:<сервер>/<база>` — таблица `dbo.Config` базы MS SQL. Строки кешируются, при следующих
  запусках докачиваются только изменившиеся;
- путь к `.cf` или `.cfe` — файл конфигурации или расширения;
- путь к `1Cv8.1CD` или к папке файловой базы.

| Команда | Что делает |
|---|---|
| `info` | имя, поставщик, версия, режим совместимости, состав по классам, модули без текста, расширения базы |
| `objects`, `modules` | списки объектов и модулей с фильтром |
| `module <имя>` | текст модуля, можно с номерами строк и диапазоном |
| `grep <текст>` | поиск по всем модулям; `--proc` показывает процедуру, в которой стоит совпадение |
| `fields [фильтр]` | реквизиты, реквизиты ТЧ, измерения, ресурсы и т.п. с типами, а первыми — стандартные реквизиты: Ссылка, Код, Наименование, Владелец, Родитель, Дата, Номер, Период, Регистратор, НомерСтроки, Счет, Субконто1…, ВидРасчета… — у всех классов, со стандартными табличными частями (ВидыСубконто, БазовыеВидыРасчета…), с типами и измененными настройками (синоним, проверка заполнения). У каждого поля — свойства не по умолчанию: индексирование, проверка заполнения, параметры выбора и связи параметров выбора, значение заполнения, формат, минимум и максимум, форма выбора, связь по типу, ведущее измерение, основной отбор; `--props` — все известные свойства поля, с подсказкой |
| `props [фильтр]` | свойства объектов: периодичность и режим записи регистров, иерархия, владельцы, длины кода, проведение, движения, ввод на основании, ввод по строке, поля блокировки данных, характеристики (откуда виды и где значения), основные формы, флаги общих модулей, обработчики подписок, методы регламентных заданий, состав подсистем |
| `predefined [фильтр]` | предопределенные элементы справочников, ПВХ, планов счетов и видов расчета деревом: имя, код, наименование; у ПВХ — тип значения, у счетов — вид, забалансовость, признаки учета и субконто; `Класс.Объект.Элемент` — элемент по имени; `--ids` — uuid элемента, он же `_PredefinedID` строки в базе |
| `rights [роль\|объект]` | права ролей: для роли — ее флаги и права по объектам с ограничениями доступа на уровне записей (RLS), для объекта — какие роли что на него дают; `--right Чтение` — одно право, `--rls` — тексты условий и шаблонов |
| `form <форма>` | управляемая форма: события, параметры, реквизиты, команды и дерево элементов с путями к данным, командами кнопок, заголовками и обработчиками событий; обычная форма: события, реквизиты, элементы по панелям и страницам с координатами, данными, заголовками и обработчиками, колонки табличных полей, кнопки командных панелей |
| `usedby <объект>` | обратные ссылки: какие документы делают движения по регистру, в каких подсистемах объект, какие подписки и задания вызывают модуль, реквизиты какого типа |
| `export <папка>` | модули в раскладке XML-выгрузки (`Catalogs/X/Ext/ObjectModule.bsl` …), свойства, типы, предопределенные элементы, права ролей и элементы форм в TSV |
| `diff <источник2>` | сравнение двух источников: модули, типы полей, свойства, предопределенные элементы и права ролей |
| `check <папка XML>` | самопроверка: сверка с XML-выгрузкой той же конфигурации |

Имена можно писать по-русски: `Справочник.Валюты.МодульОбъекта`, `ОбщийМодуль.ОбщегоНазначения`.

```bash
py -X utf8 cfgread.py sql:trade grep "ЦеныНоменклатуры" --proc --ctx 2
py -X utf8 cfgread.py "D:\Bases\Shop" module "Документ.РеализацияТоваровУслуг.МодульОбъекта" --lines 1-60
py -X utf8 cfgread.py "D:\Incoming\client.cf" diff sql:trade --fields --props
py -X utf8 cfgread.py sql:trade usedby "РегистрНакопления.ТоварыНаСкладах"
py -X utf8 cfgread.py sql:trade predefined "ПланСчетов.Хозрасчетный"
py -X utf8 cfgread.py sql:trade rights "Документ.РеализацияТоваровУслуг" --right Проведение
py -X utf8 cfgread.py sql:trade form "Documents.ЗаказКлиента.Forms.ФормаДокумента"
py -X utf8 cfgread.py sql:ut10 form "Документ.ПриходныйКассовыйОрдер.Форма.ФормаДокумента"
```

Обычно скрипт запускать самому не нужно. Попросите Claude: «посмотри модуль объекта документа ЗаказПокупателя в
базе trade», «где пишется регистр ЦеныНоменклатуры», «что поменялось в client.cf по сравнению с базой».

## Насколько можно доверять

Формат хранения 1С не документирован. Все, что знает скилл, получено опытным путем и сверено с XML-выгрузками
конфигуратора (платформа 8.3.27). Сверка прошла на девяти разных конфигурациях:
- УТ 2.3 с обычными формами, УТ 3.1, УТП 1.2 с планами счетов и расчетом;
- BAS Розница, BAS Бухгалтерия 2.1, BAS КУП 2.5, ITIL, Бухгалтерия для Украины 1.2;
- одна отраслевая конфигурация.

Источниками были MS SQL, `.cf` и файловые базы. Тексты 30 267 непустых модулей совпали с XML байт в байт, типы
117 174 полей тоже совпали. Отличие нашлось одно: ссылка на удаленный объект, которую XML-выгрузка молча
выбрасывает.

Свойства объектов лежат в описании объекта по позициям, и позиция зависит от версии формата объекта: в одной
конфигурации объекты бывают записаны разными поколениями платформы. Места 306 свойств сняты обучающим скриптом
`learn_props.py` сверкой с XML на семи конфигурациях, отдельно для каждой версии формата. Еще 15 свойств, которым
не хватило объектов с разными значениями, сняты на тестовой конфигурации с нарочно редкими значениями. На объектах
обучения верны 99,99% значений, на конфигурациях, которые в обучении не участвовали, — 99,9%. Составные свойства
(ввод по строке, поля блокировки данных, характеристики) разбираются отдельно: все 9308 значений на девяти
конфигурациях и тестовой совпали с XML.

Свойства полей (индексирование, проверка заполнения, «использование», флаги измерений, маска, быстрый выбор и т.д.)
сняты скриптом `learn_fields.py` на 113 тыс. полей тех же конфигураций, параметры выбора и их связи разбираются
отдельно, как и значения заполнения, форматы, подсказки, минимум и максимум, форма выбора и связь по типу. Сверка с
XML: 2,5 млн значений свойств полей, расхождений нет.

Типов стандартных реквизитов в хранилище нет: платформа выводит их из свойств объекта (длина кода, иерархия,
владельцы, периодичность, движения документов, корреспонденция, число субконто), и скилл повторяет ее правила. Состав
и типы сверены с тем, что сообщает сама платформа через COM, на пяти базах — четырех клиентских (отраслевая, УТП 1.2,
BAS Бухгалтерия, BAS КУП) и тестовой с нарочно редкими значениями свойств: совпали все 19 078 реквизитов. Настройки
(синонимы, подсказки, проверка заполнения) сверены с XML на тех же девяти конфигурациях и тестовой: совпали у всех
34 763 реквизитов.

Предопределенные элементы (справочники, ПВХ, планы счетов и видов расчета: место в дереве, имя, код, наименование,
тип значения, вид счета, признаки учета, субконто) сверены с `Ext/Predefined.xml` тех же девяти конфигураций и
тестовой: 11 656 элементов, все 80 760 значений совпали.

Права ролей сверены с `Ext/Rights.xml` тех же девяти конфигураций: у 2300 ролей совпали флаги и шаблоны ограничений,
все 865 854 значения прав и все 11 134 условия RLS. Права, которых роль, записанная старой платформой, не хранит,
скилл выводит так же, как платформа.

Управляемые формы сверены с `Ext/Form.xml` тех же конфигураций: 10 507 форм, 772 738 элементов. Вид, имя, место в дереве
элементов и обработчики событий совпали у всех элементов, кроме трех; события, реквизиты, команды и параметры — у всех
форм; пути к данным — у 99,6% элементов, команды кнопок — у 99,97%.

Обычные формы XML-выгрузка хранит двоичным `Form.bin`, сверять их не с чем. Поэтому они проверены по самим формам и их
модулям на тех же конфигурациях: 6326 форм, 103 665 элементов, 45 724 колонки табличных полей.
- Все виды элементов известны, каждый элемент стоит на странице своей панели.
- Обработчики событий — процедуры модуля формы у 99,5–99,7% элементов, форм, колонок и кнопок. Остальные — висячие
  ссылки самих форм.
- Все обращения модулей `ЭлементыФормы.X` нашли разобранный элемент.
- Данные разобраны у 99,5% элементов и 89% колонок. Остальные колонки стоят в основном на настройках компоновки данных.

Устройство хранения с таблицами констант описано в
[storage-format.md](1c-config-direct/skills/1c-config-direct/references/storage-format.md).

## Ограничения

- Читается конфигурация базы данных. Изменения, сохраненные в конфигураторе, но не примененные к базе (ConfigSave),
  и расширения, установленные в базе (ConfigCAS), не читаются; расширение можно прочитать из его `.cfe`.
- У заимствованного объекта в `.cfe` лежит только то, что добавило расширение. Длины кода, иерархию и прочие свойства
  такого объекта смотрите в основной конфигурации.
- Не разбираются свойства оформления элементов форм (видимость, ширина, шрифты, условное оформление), у обычных форм —
  еще привязки границ и порядок обхода.
- Модули, поставленные без исходного текста или закрытые паролем, отмечаются как модули без текста.
- Файловые базы — только формат хранения 8.3.8. PostgreSQL не поддерживается.
- Современный `.cf` (примерно с режима совместимости 8.3.17) начинается с заглушки — «пустой конфигурации», —
  а настоящая конфигурация лежит дальше в 64-битном контейнере. Скилл читает ее; старые утилиты видят только заглушку.

Скилл ничего не записывает ни в базу, ни в файлы конфигурации. Проект не связан с фирмой «1С».
